# Changelog

What changed in each Weft release. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and versions follow [Semantic Versioning](https://semver.org/). Add a line under **Unreleased** when a feature
lands; a release moves those lines under its version and tags the commit `vX.Y.Z`.

0.3.0 is the first tagged release. 0.1.0 and 0.2.0 were never tagged: their sections below group the history by day.

## [Unreleased]

### Added

- **A shared thread gets a real address, a link preview, and a choice to hide the chat — like a mini app.** Share… on a card used to give only `weft.zip/s/<id>`. Now the link lives under you, `weft.zip/@you/threads/<slug>`, with the card's title as the slug (a taken one tries `-2` … `-9`); you can rename it in the dialog, and old `/s/<id>` links redirect there once the visitor is through the gate, so the redirect never tells a stranger whose link it is. A public link now unfurls in Slack and iMessage with the card's emoji and title, its first ask (redacted, one line) and the branded card the mini apps use, with the pane capture tilted in (`/api/s/<id>/og`). Private, email and password links keep the generic preview. **Show the chat**, a new checkbox in the dialog, shares the browser pane alone when it's off: the page and its live poll send no thread items at all, and the preview's description stays generic too. With the chat on, viewers get a **Hide chat** button that gives the pane the full width. Built in `lib/card-share-slug.ts`, `lib/share-meta.ts`, `app/u/[username]/threads/[slug]`, `components/share-view/SharedCardPage.tsx`, `components/ShareCardOptions.tsx`, with `cloud_shares.slug` and `show_chat` from `supabase/migrations/20261029031448_card_share_slug.sql`.
- **📈 Growth can tell which version of Weft everyone is on.** Nothing recorded it before: the updater asks GitHub directly and every session's user agent is just `node`. Now a signed-in Mac reports its version once a day on the league sync's timer, as a release build or dev mode, and `growth_versions` counts each account once, at the version it reported last, with how many opened Weft in the last week. The panel fills as people update to a build that reports. Built in `lib/app-version-sync.ts` and `supabase/migrations/20261029075755_app_versions.sql` (docs/architecture/growth.md#versions).
- **📱 Weft on your phone: the pane is the app.** A React Native app (`~/dev/weft-mobile`) shows each of your synced cards as the page its agent last showed you, full screen. Cards that need you come first, then ones ready for review, then running ones. Swipe the bottom bar up or down to move between cards, and left or right to go back through the pages a card showed. The agent's last sentence sits under the page. A waiting question shows its options as buttons, and a tool waiting to run shows **Allow** (behind Face ID) and **Deny**. Hold the mic to talk or type a reply, Stop a running turn, start a new card in one of your projects, and the thread is one tap away. Everything goes through the same cloud commands the web board uses. On the Weft side, the web board's page and blob-URL routes now accept a phone's `Authorization: Bearer` token as well as the weft.zip cookie (`requestSession` in `lib/web-session.ts`; docs/architecture/mobile.md#the-app).

### Changed

- **📥 One button gets a new project running.** When Weft takes in a project, its screen offers **Later** and **▶ Get it running**. The second starts a card that installs the dependencies and asks for each missing key with a paste box in the thread, with the provider's page open in the pane. It then starts the dev server and shows the app. It asks for your fingerprint at most once, and lists any webhooks to register later. The old Open 🔐 / 🪝 and "Set it up in a thread" buttons are gone (`components/IntakeDialog.tsx`, `lib/intake-run.ts`).
- **☁️ Synced pictures and pages load from Cloudflare R2, so reads stop using up Supabase's egress.** Screenshots, pasted images and mini app pages on weft.zip all came through Supabase signed URLs. Every one of those reads counted in full against the free plan's 5 GB a month, and one leaky share page had already burned 1.6 GB in a day. The desktop still uploads to Supabase. weft.zip now copies each blob once to an R2 bucket, where egress is free, and serves it from there through presigned URLs. Those are signed only after the same checks as before: a `blob_mirror` row your own session can see, which is the membership check, or a live share. A blob not copied yet still loads from Supabase and gets copied after the response, a daily cron sweeps up the rest, and `pnpm r2:backfill` moves the ~4,500 existing objects in one go. The infra dashboard shows Cloudflare R2 as live with what's copied and what's left, and adds an R2 storage row. `WEFT_BLOBS_R2=off` sends every read back to Supabase. Built in `lib/r2.ts` (a SigV4 signer with no SDK, checked against `aws4`), `lib/blob-urls.ts`, `lib/blob-read.ts`, `lib/r2-mirror.ts` and `supabase/migrations/20261029105650_blob_mirror.sql` (docs/architecture/r2.md).
- **Cards stop queueing on the docs everyone edits.** Adding a line to MAP.md or the README used to claim the whole file, so every other card stopped on a "Wait, or go ahead?" prompt. Markdown is now claimed by block, a paragraph or top-level bullet under its headings, so two cards adding different lines pass each other. And a commit through `commit.sh` or a page's commit button now leaves out the lines another busy card is still writing in that doc: they stay in the working tree for that card's own commit. If HEAD or the file moved since Weft worked that out, the path commits whole, as before. Built in `lib/symbols-markdown.ts`, `lib/commit-held.ts` and `plugin/skills/done/commit.sh`.

### Fixed

- **Two cards can no longer wait on each other — the board can't lock up.** A clash prompt waits by itself: the card goes to Running and holds its edit until the card holding the code lets go. But two cards can end up waiting on each other — A holds `f.ts`, B holds `g.ts`, B's edit of `f.ts` waits for A and A's edit of `g.ts` waits for B — and then neither is ever let go. A wait only ends when its holder stops being busy, and both stay busy forever. Every card in the pair reads as "waiting", the board looks busy and nothing moves, and no button on the card can break it: both cards are already waiting, so the order buttons only re-point the yields. **A wait may only be taken on a holder that isn't already waiting on this card**, directly or through other cards. The wait graph is read from the live sessions, so a wait is checked against the chain as it stands at that moment; when the chain from the holder leads back to this card, the loop would close, so the wait is refused and the card **goes ahead** instead. It takes the whole-file claim, the holder leaves the file to it, and the holder is told mid-turn why ("…waiting back would leave you both stuck, so 'X' goes first"). The holder was the one waiting on this card, so it is the one that can be released — one of the two always keeps running. This is the same path **Others first** takes, so it covers the automatic wait too, not just the one you press: the gridlock never needs you to notice it. Every wait goes through the check, including one queued behind the request the card is showing. The graph keeps every edge, so a card waiting on two cards can't hide a loop behind its first wait. The graph and the rule are `lib/wait-chain.ts`, the refusal is `breakGridlock` in `lib/permission-wait.ts`, and **Others first** checks the chain before it yields the file (`lib/precedence.ts`), so a refused wait doesn't leave a yield pointing the wrong way.
- **A plan upgrade is noticed, not waited for.** Raising your Claude plan stops the limits applying — but only if Weft notices, and the per-model caps did not. A cap recorded in `~/.weft/model-limits.json` ("Opus ran out, until Tuesday") was only ever cleared by its own window passing; nothing cleared it when the PLAN changed. So after an upgrade Weft carried on calling Opus spent: the model menus still read "— at its limit", the New thread dialog still said "Start at 2:30am", and a card parked on Opus stayed parked. `clearModelLimit()` existed; nothing called it. Weft now compares the CLI's own weekly windows (`seven_day_opus`, `seven_day_sonnet`, the server's `model_scoped[]` rows) with the caps it holds, and frees the models that have room again — `lib/limit-upgrade.ts`. A cap is released only when the CLI reports that model's family with room AND the window it names is still open, so a window that has already rolled over is not mistaken for an upgrade. The check rides the 15-minute limit poll (`lib/limit-poll.ts`) and runs again whenever a thread starts (`lib/runner-turn.ts`), so a card that starts after the upgrade is not gated by a stale cap. **Every card parked on a freed model restarts on its own**, and says why: the chip reads "Resumed · plan upgraded" instead of "Auto-resumed", which is a window resetting on its own (`lib/limit-resume.ts` `resumeParkedOnModels`, `card.autoResumedReason`). A card on a model that was not freed is left alone — it was never parked by that cap. The new module is `lib/limit-upgrade.ts` with its tests beside it; `lib/limit-poll-upgrade.test.ts` drives the poll end to end, and `components/CardMarks.test.tsx` covers the chip's two reasons.
- **The infra dashboard reads its numbers again, and the first real egress read found a leak and stopped it.** The repo-analysis report's database half had been answering a 500: `infra_live()` counted `cloud_thread_items` with a full scan, which took 6–8 s and ran into PostgREST's 8 s statement timeout. An index on `cloud_thread_items(at)` brings the call down to about 0.2 s (`supabase/migrations/20261029083040_thread_items_at_index.sql`). The egress half had never worked: Supabase removed the `logs.all` endpoint, and the new one answers at most 1,000 rows out of ~86k log lines a day. So `readEgress` now asks Supabase to do the sum (`EGRESS_SQL` in `lib/infra-live.ts`) and adds up a handful of rows. That first real read showed **1.6 GB of egress in a day, 99% of it one 400 KB thumbnail downloaded 3,980 times.** An open share page polls every 4 s, every poll signed the card's thumbnail again, and a new signed URL is a new `<img src>`, so the browser fetched the picture again each time. The share viewer now keeps the URL it already has until it's within 10 minutes of expiring (`mergeBlobUrls` in `lib/share-view.ts`), so one open share tab downloads a picture once an hour instead of about 800 times.
- **Synced pages render again instead of showing their HTML source.** Supabase Storage hands HTML back as plain text, so a card's page on the weft.zip board's pane and in the phone app came up as raw markup. Pages whose bytes are HTML now go out as HTML, still inside the same sandbox (`restoreHtmlType` in `lib/blob-read.ts`, `app/api/web-board/[orgId]/page/[sha]/route.ts`).
- **A failed clone no longer leaves a broken checkout on a worker.** A worker now clones into a hidden temporary folder and moves it into place only once every file is out, so a folder at a project's path always means a complete clone, and sending the run again clones afresh instead of starting a card in a half-made tree. A repo that uses Git LFS is spotted before its files are written: with git-lfs installed it fetches real files, not pointers, and without it the clone stops with a plain message saying what to install. `install/worker.sh` now installs git-lfs too. In `lib/worker-paths.ts`.

## [0.6.6] - 2026-10-29

### Added

- **Issue cards now stand out, and a project can work them itself.** Each project picks where its imported GitHub issue cards land, in the GitHub drawer under the sync switch: **Backlog** (what it did before — a cold card, yours to pick up), **Needs you** (the card is made there, so a fresh import is visible at a glance and still follows its issue until you run it: a new label reaches it, a closed issue archives it), or **Run** (the card's thread starts at once and the agent works the issue, parking in Needs you when it needs a decision and going to Review when it finishes, exactly as any other thread does). A **Run** card can be checked before any work happens: **Checks with** names the skill that runs as the card's first turn, and **Works as** names the agent that works it. **Design the agent** starts a **new thread** that designs that agent for you: Weft does not ask the questions, the thread does — it asks what it needs to know, one question at a time, then writes the soul and saves it as a real agent whose soul opens every system prompt its threads get. The thread opens on its own page: the brief it is running on and what happens next, written before the turn starts so the pane has something current the moment it opens. The workflow is per project and saved with your settings; changing it changes where the *next* cards land, and the cards already on the board stay where they are. The landing and its skill and agent live in `lib/issue-landing.ts` and `lib/issue-run.ts`, the designing thread in `lib/agent-thread.ts` with its brief page in `lib/agent-brief-page.ts`, the drawer in `components/IssueWorkflowPicker.tsx`, and the route in `PATCH /api/github/issues` and `POST /api/agents/design`.
- **The Weft Runner is designed: a headless agent runner on a host that does the compute for a card, while the board stays on your laptop or on the web at `<workspace>/board`.** Reading the code first turned up the fact the design rests on: Weft already has a remote *control* plane (the web board commands a Mac across the network through `cloud_commands`) but no remote *compute* plane (the CLI always spawns on the board's own machine). A runner is therefore not a new transport but a second implementation of the executor behind that same command bus — the `run` kind carries a `Spec` (`lib/runner-state.ts`), and the turn comes back through the same `handle(id, session, msg: SDKMessage)` seam the Codex and Goose runners already use (`lib/runner-turn.ts:36`), so the thread rendering, the reply box, the permission prompts and the web transport are all unchanged. A `cloud_hosts` registry with heartbeats turns the web's "Waiting for your Mac" into a real liveness signal, and command leases replace the rows a crashed runner would leave `claimed` forever. The design also names the twelve places a host is not "the Mac, but headless" — the guards and cross-card claims are in-process today and become distributed, paths and repos need host-relative identities, the pending permissions have to become state rather than a promise, the worktrees need a Linux implementation, and the 🔐 vault needs a host-scoped key. The phases: the daemon alone (a Mac card running on a server) → addressing and liveness → shared claims → host-side MCP and secrets → the host's own board, where this converges with headless server mode. The design is in `docs/architecture/runner-host.md`; the ROADMAP's "Remote runners" moves from P3 to P2.

### Changed

- **The Esc view hint is now a loud toast** — it was a grey box in the bar's own grey, 11.5px, gone in 2.6 seconds, and it read as a tooltip rather than an announcement. It is now big type, an accent tile carrying the view's icon, a bright accent border and a wide glow, with a short pop-in so it reads as an announcement. It stays up for 4 seconds, and says what the next Esc does ("List view · hit Esc again to switch to board view") instead of a vague "Esc goes back". It is one row and never wraps. An absolutely-positioned box with no width shrank to its content and then wrapped its text into a narrow column, which left the icon adrift from the words and stranded the ✕ between them, so it now carries `w-max` and `whitespace-nowrap`. **The next Esc puts the toast away** instead of flipping the view again — the toast advertises that Esc does something, so Esc has to do it. The flip itself still works the same: the toast is driven by the board's own Escape layer, so it appears on exactly the Escape that moves the view. **Every flip pops the toast afresh.** The flip's id counted the flips but nothing read it, so a second Esc left the toast sitting there already grown, with its entrance long over. It is keyed on the id now, so each flip remounts it and the pop-in plays again. And the toast's ✕ was wired through an optional prop that defaulted to a no-op swallowing the click, though the board has always passed it; it is required now. The toast is `components/ViewHint.tsx` with its state and timer in `lib/use-view-hint.ts`, the flip's hook `lib/use-escape-view.ts` (whose extra inputs are one options object, not a list of six), the pop-in and glow in `app/globals.css`, and the bar that hangs it under the toggle in `components/ProjectBar.tsx`.

### Fixed

- **The dictation key answers to Command+Option+' and stops the mic.** The rebindable binding is a set of modifiers rather than an exact combination, so the default `⌥'` now fires on `⌘⌥'` too — the combination people reach for when the bare one is taken. Pressing the key again while the microphone is still opening cancels the recording that is starting, instead of leaving it running with nobody listening or opening a second microphone on top of it (`lib/shortcuts.ts`, `lib/use-dictation.ts`, `lib/use-composer-keys.ts`).
- **The packaged app starts again — it had been dying on launch with "Cannot find module '@supabase/supabase-js'".** The shared vault added a Supabase client to Electron main, but electron-builder's `files` list drops the whole top-level `node_modules` (`!node_modules${/*}`), and the package was never named back on the list. It was in `package.json`'s dependencies and in the Next server's standalone bundle, so the dev build and every dependency check were happy — but the *shipped* app's `node_modules` is only the allow-list, and the client wasn't on it. Every packaged build since died in the main process before a window opened, and no test could see it, because the tests run against the repo's `node_modules`, where the package is present. **The list is now derived rather than hand-kept.** `scripts/electron-runtime-deps.mjs` computes the closure of packages Electron main needs at runtime — the bare `require()`s out of `electron/*.cjs`, then the runtime requires out of each package it finds, transitively — and `pnpm dist` writes it into `build.files` before packaging. A new `require()` ships with its package instead of waiting for someone to remember. Both the CommonJS and the ESM entry are read, because a package's `main` can vendor a dependency its `module` build imports (realtime-js's `dist/main` vendors its own phoenix, its `dist/module` imports `@supabase/phoenix`). **The built app is checked before it ships.** `scripts/verify-packaged-app.cjs` reads the archive itself — a package counts as shipped only if `app.asar` holds it, never by resolving from the repo's `node_modules`, which has everything and would hide a broken build — and then loads the packaged `account-client.cjs` out of the archive and builds a Supabase client from it. `electron/packaged-deps.test.ts` fails if `build.files` drifts from the closure. The packaged app's bundled **pnpm** (which already ships in `Contents/Resources/toolchain`) is checked too: `scripts/verify-packaged-toolchain.cjs` confirms it runs, matches `packageManager`, and can install a project's dependencies. The packaging section of `docs/architecture/desktop-shell.md` says what the allow-list is and how it is derived. **The app now checks its own bundle before anything needs it.** The derivation and the build check catch a missing package before it ships, but a bundle can still arrive broken another way — an interrupted install, a half-copied update — so at boot the app reads its own `app.asar` and says what is missing: *"Weft couldn't find some of its own files (missing from the app bundle: @supabase/supabase-js). Reinstall Weft to repair it."* instead of dying on a require with a native "A JavaScript error occurred in the main process" dialog nobody could act on. The check reads the *bundle*, not the machine: inside `app.asar` Node's resolution walks out of the archive and finds the real `node_modules` next to the app, so a plain `require.resolve()` would report "found" for a package the bundle doesn't have — the same trap `verify-packaged-app.cjs` documents, and the first version of the check fell into it and called a broken bundle good. The Supabase client is now required lazily, so a bundle missing it still opens a window and can say so. **An auto-update runs `pnpm install` — for the one tree that needs it.** Squirrel.Mac replaces the whole `.app` bundle, so an update brings the app's own dependencies *with* it: `app.asar`'s packages and the Next standalone bundle are already installed when the app restarts, and re-installing them would write a `node_modules` folder nothing reads. The one tree installed separately from the bundle is the toolchain's puku tree, so that is what `pnpm install` runs against — after an update, and only then, in the background, because the board never waits for it. The app knows an update landed by the version changing since the last launch (`~/.weft/updated-version`), so an ordinary relaunch installs nothing and only checks the tree. The check and the install live in `electron/runtime-deps.cjs`, `electron/toolchain-install.cjs`, `electron/updated-since.cjs` and `electron/boot-deps.cjs`, with tests beside them; `docs/architecture/updates.md` says what an update brings and what it installs.
- **Two bugs from GitHub are fixed: the achievements screen can always be dismissed, and logging in with Claude no longer leaves the app stuck.** **The achievements screen keeps its buttons on screen.** The pop-up had no height cap and nothing to scroll: the hero picture, the medal and the badge list pushed the buttons below the fold, and on a short window they fell off the edge entirely, so the screen could not be dismissed at all. The panel is capped now, the badges scroll above, and the buttons sit in a pinned footer that stays put at any window height (`components/AchievementPopup.tsx`). **Logging in with Claude no longer leaves the app stuck.** Three things went wrong at once. The panel read the logins once and then went on saying "Not logged in" after a successful login, so pressing Log in again felt necessary. Pressing it again was the freeze: the second login replaced the first, killing its `auth login` process mid-flow, so the credential never landed and the two logins fought each other — the copilot's "could not be refreshed" was the CLI trying to reuse the stale token. The server now joins a login that is already under way instead of replacing it, so a login is never killed (`lib/login.ts`). The panel re-reads the logins every two seconds, so a login finished in the browser shows up on its own, and the Log in button is replaced by a "Logging in" line while one is under way, so there is nothing to press twice (`components/CliLogins.tsx`). The welcome screen's own Log in button is safe for the same reason: the server joins the running login instead of starting a second one. `components/CliLogins.test.tsx` is new — the panel had no test at all — and `lib/login.test.ts` and `components/AchievementPopup.test.tsx` cover the rest. Each new test was checked against the unfixed code: it fails there and passes here.

## [0.6.5] - 2026-10-28

### Added

- **Your 🔐 secrets now follow you across machines** — a vault can be shared with your workspace, and every Mac you own (and every teammate you invite) reads and writes the same secrets. The server never holds a value: your device has a keypair, the vault's key is sealed to each device's public key, and each secret is encrypted under that key before it leaves the Mac. The server stores ciphertext and nothing else, so it can only ever be trusted with what it cannot read. **Sharing it** — the drawer's **Share this vault with `<workspace>`** turns a local vault into a shared one; the header then shows the workspace's name, a *shared* badge and the key version. A teammate's machine is added by fingerprint: both sides show the same string, you compare them out of band, and only then is the key sealed to that device. **Devices** is a new tab on the workspace's Team page. The desktop's keypair never leaves the machine it was made on, and Weft's servers can't substitute their own — a fingerprint that doesn't match stops the grant before any key is produced. **Working in it** — the drawer pulls changes when it opens and follows them live, a teammate's edit shows in the event log beside the secrets (who did what, never a value), and if your change loses a race the row says so: "Sam changed API_KEY in development — keep your edit?", with both ways out. Reads work offline from the local shadow; writes made offline queue up and drain in order, and nothing is dropped while a conflict is unresolved. **When people leave** — removing a teammate can **rotate** the shared vaults: the key version is bumped, a fresh key is made on your own Mac and sealed to the machines that stay, and every value is re-encrypted under it, so the plaintext they held stops being worth anything. Weft then names the values to change at their providers — the *names* only. A vault's **recovery key** is 24 words that open it when every machine is gone: Touch ID asks, the words appear once to write down, Weft keeps no copy, and asking again makes a new one so the old words stop working. The schema is `supabase/migrations/20261027163113_team_vault.sql`; the crypto is `electron/vault-crypto.cjs`, the sync engine `electron/vault-sync.cjs`, the grant flow `electron/vault-grant.cjs`, the rotation `electron/vault-rotate.cjs` and the recovery key `electron/vault-recovery.cjs`, with the workspace side in `app/[orgSlug]/team/devices/` and `app/api/team/vaults/`.
- **Esc now says where it took you** — pressing Esc on a bare board flips between the columns and the list sheet, and a small pane now pops under the board/list toggle naming the view you landed in ("List view. Esc goes back."). It hangs off the toggle rather than taking a row, so it costs no vertical space on a small screen, and it closes itself after a moment or on its ✕. The hint is driven by the board's own Escape layer, so it appears on exactly the Escape that moves the view: with a thread, the new-thread dialog, the browser pane or a closable drawer open, or with Esc typed in a field, the view stays put and no pane appears. **Escape from a page in the browser pane now reaches the board too** — a focused page swallowed the key, and it arrived as a raw key-down that the pane's replay dropped, so the flip never happened from inside a page. The pane is `components/ViewHint.tsx` with its state and timer in `lib/use-view-hint.ts`, the flip's hook `lib/use-escape-view.ts`, and the pane's Escape rule `electron/pane-escape.cjs`.

### Changed

- **The model picker closes when you pick, and every row is a model** — no more "Let Claude Code choose" or "Let the model choose" in a model menu: each row is the model that will actually run, and a menu with nothing picked shows the model its CLI runs. Codex and Goose, whose model lives in their own config, each keep one row for it (**Codex's configured model**, **Your BYOK model**). The list is taller, so more models fit before it scrolls, and it closes on a pick — the field sits inside a label, and the click that used to refocus the input and reopen the list is cancelled now. **The Goose group lists your provider's models, not a fixed set** — a menu's Goose rows are the provider you set up (Settings → Models → Bring your own key): OpenRouter's `anthropic/claude-opus-4.1` never shows under Anthropic any more, and a local Ollama shows the id it runs. A Goose id is recognised through the provider catalog, so a model still routes to Goose, and a Goose row's value is prefixed so it can't be mistaken for another CLI's same id. **Name your models** — Settings → Models → Bring your own key has a **Model names** section: a name beside a model id ("Big Opus" for `anthropic/claude-opus-4.1`), and every model menu in Weft shows that name with the id beside it. The id field offers your provider's own model ids as suggestions. The picker is `components/ModelTypeahead.tsx` and `components/ModelSelect.tsx`, the rows `lib/model-options.ts` and `lib/new-thread.ts`, the provider's models `lib/goose-provider.ts`, and the naming UI `components/GooseNamedModels.tsx` with `lib/use-named-models.ts` and the settings route.

### Fixed

- **A Goose model is no longer dropped when a thread starts.** Picking a model from a Bring-your-own-key provider and starting a thread with it ran on the provider's default instead of the model you picked, with nothing to say so: the id was checked against a pattern that allowed neither the "/" in an OpenRouter id (`anthropic/claude-opus-4.1`) nor the ":" in a local tag, so it was read as no model at all. The check now allows the characters a real model id uses, and the "goose:" prefix a picker adds comes off at the card's edge, because a card's model is the id the CLI takes. (`lib/new-card.ts`)

## [0.6.4] - 2026-10-27

### Changed

- **The copilot is now your product partner, not a second inbox.** It helps you decide what to build next, shape an idea into cards and keep the code healthy. It no longer recites the board. The launcher's number (90 and climbing) is now a dot that only lights when the copilot has said something you haven't read, and the peek shows its latest idea instead of a list of cards. It also speaks first, at most three times a day and never from 21:00 to 7:00: a morning idea drawn from your roadmap, recent commits and analytics, and a refactor worth doing after work lands in a project. When it has nothing worth your time, it answers QUIET and the check-in leaves the chat. Turn this off with "Checks in on its own" in the copilot's name menu. (`lib/copilot-initiative.ts`, `lib/copilot-initiative-run.ts`, `lib/board-tools-trust.ts`, `components/CopilotHider.tsx`, `components/CopilotPeek.tsx`, `lib/copilot-sources-product.ts`)

### Fixed

### Security

- **The Slack install no longer needs the app's Client Secret.** Weft's incoming-webhook install asked for the app's Client ID *and* Secret, and the Secret is the one value a person has to copy by hand out of a console page. The app now uses **PKCE**: the authorize step sends a challenge instead of the secret, and the exchange sends back the verifier that made it. The secret is never needed for the exchange at all — the install needs only the public Client ID, and the Client Secret, if you set one, is now just the key that signs the install state. - **The local API fails closed without its launch token.** With no token file on disk, Weft's server used to skip every token check; now reads without the board's header and every elevated write are refused. - **The onboarding-stats collector is rate-limited.** weft.zip's `/api/telemetry/collect` now takes 60 posts a minute per address (429 with `retry-after`) and refuses browser posts from other sites, so a script can't flood the stats. `lib/telemetry-limit.ts`, `lib/fixed-window.ts`.

### Security

- **A local process can no longer read the board.** Once the desktop app writes a launch token, every API route needs it — reads included, not just writes. Before, a read passed on the localhost Host check alone, so any process that reached the port (a browser extension, a malicious `postinstall`, another local app) could read `/api/webhooks` (project paths and the *names* of the vault's secrets), `/api/projects`, `/api/game`, `/api/github` and 15 more. Only Weft's own window is given the token (`electron/api-token.cjs`). The per-route `sensitive` flag is gone: it existed to mark the six routes that leaked and no longer changes any verdict (`lib/guard.ts`; pentest 2026-10-23, P-1).
- **A thread can no longer approve itself through the board view.** `mcp__board_view__click` and `type_text` refuse anything inside `data-human-only`: the permission panel (Allow, folder This card / Always), the reply box while a question waits, the mode picker and Settings. Screenshots and reads still work (`electron/board-view.cjs`; pentest 2026-10-20, P-1).
- **Synced threads are redacted before they leave the Mac.** Cards, thread items and long tool outputs go through the share redactor (`findSecret` + the entropy pass) before the upsert, so a key that reached a thread never lands in rows every workspace member can read; the raw text stays local (`lib/cloud-sync-redact.ts`; P-2).
- **"Always allow" on a vault command lasts only until the code changes.** A `secret_run` rule now also pins a fingerprint of the folder's tree (HEAD, the diff against it, untracked files' bytes), so a thread editing a file the approved script runs makes Weft ask again; outside a git repo it always asks. Dev-server grants are unchanged (`electron/run-rules.cjs`; P-3).
- **Power writes need the launch token.** Answering a permission, changing settings, allowing a folder, running `!` shell, loosening a card's mode or granting it a read scope now refuse the bare `x-weft-token: 1` a thread's `curl` can send; ordinary card moves and creates still take it (`lib/guard.ts` `elevated`; P-4).
- A webhook relay delivery can no longer climb out of its target's path (`..`, `%2e%2e`) to another local route, and the relay drops `x-threadboard` from a stranger's request. Account, settings and services reads need a per-launch token the board window adds itself (`electron/api-token.cjs`). `weft://` links only act from a page under `~/.weft`, not any `file:` page.
- The email forwarder scrubs CR/LF/NUL from the parsed From display name, the subject, the alias and the round-tripped `X-Forwarded-*` headers (and every entry in the reply-to list), so an attacker mailing to `@weft.zip` with a crafted `From:` can't smuggle extra headers into the forwarded mail. Five new tests in `lib/email-forward.test.ts` cover the cases (pentest 2026-10-20, F-7; `lib/email-forward.ts`).
- **A hosted mini app's manifest can no longer point its Supabase read at a host of its choosing.** A named Supabase read sends the app author's real `SUPABASE_SECRET_KEY` as a bearer token to the URL `weft-app.json` declares, and that URL was copied into the share row with only a `typeof` check — so a manifest naming an attacker's host had weft.zip hand the key over on the first read. `supabaseUrl` must now be an `https` Supabase project URL (`.supabase.co` / `.supabase.in`, no credentials, no port), checked both when the manifest is reduced and again at read time so rows written earlier can't leak either (`lib/app-folder.ts` `safeSupabaseUrl`, `app/api/a/[id]/read/route.ts`; pentest 2026-10-20, F-11).
- **…and neither can a saved local one.** That fix reached only the hosted route; the local read path is a second implementation of the same read, and it had no such check — a data app saved from a folder could name any host and collect the project's `SUPABASE_SECRET_KEY` as `apikey` + `Bearer` on the first read. `supabaseUrl` is now judged by the same rule in both places, at manifest load and again before the secret is read, and the request is built on the validated origin rather than the raw string (`electron/app-data-reads.cjs` `safeSupabaseUrl`, `electron/app-data-frame.cjs`). A parity test asserts the CJS copy and the `.ts` original agree on every case, so the next fix can't land on half the code again (`electron/app-data-reads.test.ts`).

### Security
- The Weft account's refresh token is sealed in the Keychain by Electron main instead of a plain `~/.weft/account.json`.

### Changed
- Auto is now the fallback permission mode everywhere: cards a thread starts with no parent card, and a new copilot,
  follow Settings → Default mode instead of `default`.
- The ▲ Vercel, Supabase and BlastCP drawers open on their last status (kept in memory and localStorage across
  restarts) instead of "Asking Vercel…", refresh it quietly behind, and ask the service at most every 30s on
  focus. The three hooks share `lib/use-linked-status.ts`.
- The Weft account sign-in's OAuth redirect target is now `weft://account-callback`, so the URL is stable across
  Weft restarts (the dev server picks a fresh port every launch); plain `next dev` still uses the loopback HTTP
  origin. Electron main's `weft://` handler forwards the code to a new `/api/account/weft-callback` route, which
  exchanges it against the PKCE verifier kept in the session file. In `npm run desktop` (dev Electron), a wrapper
  `Weft Dev.app` at `~/Applications/Weft Dev.app` is built by `scripts/dev-protocol.cjs` to declare the scheme in
  its Info.plist (the dev Electron.app can't), registered with LaunchServices, and forwards the link to the running
  dev Electron via a `--weft-link=weft://…` argv (parsed by `electron/argv-link.cjs`).

  keeping each column's shape.

  committing, code review, docs and refactor skills, as well as refactor titles.

### Removed
- Builder card: the Thrift attribute (cost per shipped card) is gone; seven attributes remain.
- The reply box's "Also running here: …" line: in a busy repo it always showed. The card's "+N here" chip and
  the New thread dialog's line stay; symbol claims (on the roadmap) will warn at the moment two cards clash.

### Fixed
- An edit that makes a route file (`app/**/page.tsx`, a layout, a `route.ts`, middleware) import a module that isn't
  there yet is now refused before it lands, with the file to write first: one such import took the board and every
  `/api` route down for ~5 minutes (`lib/route-import-guard.ts`, docs/bug-fixes/010).
- A parse error in `components/home/Home.tsx` no longer 500s the board. The home is now loaded through
  `loadHome()` in `lib/home.ts` (a cached dynamic import) from both `app/page.tsx` and `app/home/page.tsx`, so
  `app/page.tsx` no longer static-imports a module it doesn't render in dev; `/home` shows a small fallback when
  the home fails to load (`docs/bug-fixes/011`).
- The packaged app no longer crashes at launch with "Cannot find module 'libsodium-wrappers'": the Electron bundle now
  carries the main process's two packages, `libsodium-wrappers` (the 🔐 vault) and `node-pty` (the terminal drawer).
- Threads, a card's dev server and `!` commands no longer inherit Weft's own `next dev` env (`NODE_ENV=development`,
  `PORT`, `__NEXT_*`, `NEXT_PRIVATE_*`, `NEXT_PUBLIC_*`, `TURBOPACK*`), so `next build` in another project prerenders
  again instead of failing on `/_global-error` (`lib/env.ts`).
- The "Couldn't sign in to Weft" dialog shows plain text (it showed `Couldn&#39;t`) and no longer repeats its title in
  the message (`electron/account-link.cjs`).
- A card waiting on you (a question with Answer, or Allow/Deny) can be dragged to Backlog, Review or Done to park
  it; its question stays open there, and answering runs the turn on. Only running cards and the copilot stay put.
- A thread can't throw away other cards' uncommitted work: a hook (`lib/git-guard.ts`) turns away `git stash` (but
  `list`/`show`), `git reset --hard`, checking out or restoring paths over the worktree, and `git clean -f`, and says how
  to commit by path, read a clean copy with `git show HEAD:path` or commit through a temp index instead. A scratch clone
  in the temp folder is left alone.
- A thread can't restart Weft while other cards' turns run: a hook (`lib/restart-guard.ts`) turns away `kill`, `pkill`,
  `killall` or port-freeing aimed at Weft's own server, app or port, and a second `npm run dev` / `electron .` in
  Weft's folder, saying how many turns it would cut off. Alone on the board it's allowed; your project's dev server always is.
- A card whose CLI goes on working after its turn ended shows Running again, so a restart then finds it cut off instead
  of leaving it in Review with a tool call and no reply.
- Weft opens on the project you had selected last, with its sort order. They were kept per port, so a launch
  that started the server on another port forgot them (`lib/view-prefs.ts`).
- The board no longer fails to build when a card menu loses the library's star menu: ☆ stars or unstars a card in one

- A thread's big heredoc no longer stalls the board's server in the secret guard: a 1.2 MB script with a few `{a, b}`
  groups took 300+ s (256 copies of itself, every token path-checked) and now takes ~0.2 s (`lib/secret-guard.ts`).
- The secret guard no longer stops a thread editing code that mentions `.env`: a `sed -e` script or a Python or

- Threads write their pane pages (plans, commit checklists, how-tos) to `~/.weft/show/`, not `/tmp/weft-show/`, so
