🏷️ BYOK models, named done

A user gives their Goose models names in Settings → Models → Bring your own key, and picks them by name in every model menu. A name says this runs on Goose — so the row stays in the Goose group even when another CLI's list names the same id, and the thread starts on Goose with the bare id.

The seam

StepBeforeAfter
backendOf() in ModelSelect looked the id up in the shared MODELS list the name decides the CLI; names are a Goose-only list
Picker value bare id — collided goose:<id> — the prefix tells them apart
resolveModel() "puku-ai-2.8" → puku prefix seen → backend: goose
bareModel() — prefix taken off before the id reaches the CLI

What was fixed

✓ A named model was filed under the wrong CLI

backendOf() only found ids in the shared MODELS list, so "puku-ai-2.8" — puku-cli's own id — sent a Goose row to puku-cli. Now every named model is a Goose row, and its value carries the goose: prefix through every hop.

  • components/ModelSelect.tsx — the named memo
  • lib/model-options.ts — gooseNamed(), gooseRowValue()
  • lib/new-thread.ts — resolveModel, bareModel

✓ The configured model only showed with a provider set up

gooseNamed() was dead code and the configured gooseModelId only appeared when a provider was chosen. The model the provider runs is now always a row, named or not.

  • components/ModelSelect.tsx
  • lib/model-options.ts — gooseNamed()

✓ A save left the menus stale

The pickers read names from the board's store, so a save had to re-read them — otherwise the old names lingered until a board reload.

  • components/GooseNamedModels.tsx — loadNamedModels() after a save

✓ Dead code and a duplicate validator

Four unused functions and a second validator for one setting, both removed — the setting is owned in one place.

  • lib/goose-models.ts — namedModels, setNamedModels
  • lib/settings.ts — gooseNamedModels()

The one thing worth remembering: a name is not a label — it is a claim about where the model runs. "puku-ai-2.8" is puku-cli's own id, but a user who named it in the Goose section is serving it through Goose. So the prefix, not the id, is what carries the truth from the menu to the runner.
